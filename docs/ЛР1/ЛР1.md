# Лабораторная работа 1

## Изучение паттерна Strategy

Для изучения был выбран паттерн Strategy (Стратегия), расположенный в каталоге `DesignPatterns/Implementation/Behavioral/Strategy`.

Паттерн Strategy позволяет определять несколько вариантов выполнения алгоритма и выбирать нужный вариант независимо от объектов, которые используют этот алгоритм.

В рассмотренном примере реализована сортировка сотрудников. Класс `Employee` содержит идентификатор и имя сотрудника. Для сравнения сотрудников предусмотрены два класса: `EmployeeByIdComparer` и `EmployeeByNameComparer`. Оба класса реализуют интерфейс `IComparer<Employee>`, но используют разные критерии сравнения.

Класс `EmployeeRunner` создаёт список сотрудников и выполняет его сортировку. В активном коде используется лямбда-выражение для сравнения по имени. Также в примере показан альтернативный вариант сортировки с помощью `EmployeeByIdComparer`.

Главное преимущество такого подхода заключается в возможности менять алгоритм сортировки без изменения класса `Employee`. При необходимости можно добавить новый класс сравнения, реализующий `IComparer<Employee>`, например сортировку по идентификатору или другому параметру.

Таким образом, паттерн Strategy отделяет алгоритм от объекта, который его использует, и позволяет выбирать подходящий вариант поведения.

## Анализ нарушений SOLID в LogProcessingModule

| Принцип | Место нарушения | Причина |
|---|---|---|
| SRP | LoadConfig() | Чтение конфигурации — отдельная ответственность |
| SRP | OpenSinks() | Управление подключениями и открытием приёмников |
| SRP | ParseLine() | Разбор входных строк |
| SRP | Format() | Форматирование логов |
| SRP | Write() | Маршрутизация и запись |
| SRP | Run() | Управление всем процессом обработки |
| OCP | OpenSinks(), Write() | Добавление приёмника требует изменения switch |
| OCP | Format() | Добавление формата требует изменения switch |
| OCP | SeverityToInt() | Добавление уровня требует изменения метода |
| LSP | ILogSink | Не все реализации способны выполнять все операции интерфейса |
| ISP | ILogSink | Интерфейс объединяет несвязанные обязанности |
| DIP | FakeDbConnection, StreamWriter | Зависимость от конкретных реализаций |
| DIP | File.Exists, File.ReadAllLines, File.ReadLines | Прямая зависимость от файловой системы |
