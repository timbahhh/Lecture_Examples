# Лабораторная работа 2. IoC, DI-контейнер и Singleton

## Цель работы

Изучить внедрение зависимостей, работу DI-контейнера и различия между классическим Singleton и регистрацией `AddSingleton`.

## 1. Реализации ConfigService

Реализованы три варианта сервиса конфигурации:
- `ClassicConfigService` — классический Singleton со статическим методом `Instance()`.
- `LazyConfigService` — Singleton с использованием `Lazy<T>`.
- `ConfigService` — обычный класс с публичным конструктором, время жизни которого контролирует DI-контейнер.

Все три реализации используют интерфейс `IConfigService`.

## 2. Тестирование Singleton

Созданы тесты для проверки всех реализаций. Продемонстрирована проблема общего состояния классического Singleton: результат теста зависит от порядка выполнения. Проблемный тест отдельно проходит, а при совместном запуске обнаруживает конфликт состояния. Он отключён для сохранения успешного CI.

Обычный `ConfigService` позволяет создавать независимые экземпляры, поэтому подобной проблемы нет.

## 3. Композиционный корень

Для сборки приложения использован `Microsoft.Extensions.DependencyInjection`.

Зависимости передаются через конструкторы. Регистрация сервисов выполняется в `Program.cs`. Обращение к `IServiceProvider` оставлено только в точке входа. Для управления созданием объектов используется DI-контейнер.

## 4. Профили конфигурации

Добавлены два профиля: `console` и `file`. Выбор профиля выполняется через файл `profile.txt`. Изменение профиля позволяет переключать поведение приложения без перекомпиляции.

## 5. Singleton и AddSingleton

Классический Singleton предоставляет глобальную статическую точку доступа и сохраняет общее состояние, что затрудняет тестирование.

`AddSingleton` управляет временем жизни экземпляра через DI-контейнер. Зависимости передаются через конструкторы, а реализации можно заменять, что упрощает тестирование и снижает связанность кода.

## Вывод

В ходе работы реализованы три варианта `ConfigService`, изучена проблема общего состояния Singleton, настроен DI-контейнер и реализовано переключение профилей конфигурации. Сборка проекта и тесты выполняются успешно.
